# gtt-sidebar 优化说明

> 本项目基于 [bitlamas/gtt-sidebar](https://github.com/bitlamas/gtt-sidebar) 改造。
> 原项目是一个 C# / WPF 编写的 Windows 桌面侧边栏工具，用于填充 14 寸笔记本屏幕上的空白区域。
> 本文档记录在原有基础上所做的全部优化与改造。

[← 返回项目主页](../README.md)

- **框架**：.NET Framework 4.7.2（WPF）
- **依赖**：Newtonsoft.Json 13.0.3
- **窗口**：宽度可调（默认 122px），贴屏幕左/右边缘，置顶显示，可最小化到系统托盘

## 二、失去焦点贴边隐藏

这是一个新功能：侧边栏在失去焦点后自动滑出屏幕，鼠标碰边缘再唤回。

### 交互设计

| 场景 | 行为 |
|---|---|
| 失去焦点 | 延迟 600ms 后平滑滑出屏幕，仅保留 **3px** 边缘在屏幕内 |
| 鼠标触碰贴边一侧的**屏幕边缘中段** | 自动滑回显示 |
| 托盘图标双击 | 唤回显示 |
| 设置窗口 / 备注弹窗打开期间 | 自动隐藏被抑制，避免操作到一半侧边栏跑掉 |

#### 感应区范围（避免遮挡窗口按钮）

鼠标触发区**不是**整条屏幕边缘，而是「边缘上的一段垂直带」，顶、底各留白：

```
┌──────────────┐  ← 屏幕
│              │  ← 顶部 25% 留白：不触发
│              │     （避开窗口右上角的关闭/最小化按钮）
├──────────────┤
│              │
│   感应区      │  ← 仅这一段响应唤回
│              │
├──────────────┤
│              │  ← 底部 15% 留白：不触发
└──────────────┘     （避开任务栏托盘区）
```

这样鼠标移向窗口右上角去点关闭按钮时，不会误触发侧边栏滑出、反把按钮挡住。

### 可配置项

设置窗口「窗口与布局」区新增，托盘右键菜单也有开关：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `AutoHideOnFocusLost` | `true` | 是否启用 |
| `AutoHideDelayMs` | `600` | 失焦后延迟毫秒数（0–2000） |
| `AutoHidePeekPx` | `3` | 隐藏后露出屏幕的像素宽度 |
| `AutoHideEdgeTopRatio` | `0.25` | 感应区顶部留白（占屏幕高度 0–0.5） |
| `AutoHideEdgeBottomRatio` | `0.15` | 感应区底部留白（占屏幕高度 0–0.5） |

全部持久化到 `settings.json`。两个留白比例在设置窗口中以百分比滑块呈现（0%–50%），
并带联动保护：两者之和超过 80% 时自动压制另一个，保证感应区至少保留 20% 高度。

> **向后兼容**：新增的两个字段在 `WindowSettings` 中带有默认值初始化器，
> 因此旧版 `settings.json`（不含这两个字段）反序列化后会自动套用默认留白 0.25 / 0.15，
> 不会退化为 0（那会导致感应区重新贯穿全屏）。此行为已用独立测试程序实测验证。

### 实现要点（踩过的坑）

实现过程中解决了三个关键问题，这里记录以便后续维护：

**1. 动画残留值污染属性**

WPF 的 `DoubleAnimation` 配合 `FillBehavior.HoldEnd` 会**覆盖** `Left` 属性值。
动画结束后必须显式清除动画再写回，否则后续读取到的是动画残留值，滑回位置会错乱：

```csharp
_window.BeginAnimation(Window.LeftProperty, null);
_window.Left = targetLeft;
```

**2. 初始化顺序**

自动隐藏管理器必须在 `ApplySettings()` **之前**创建，
否则记录初始显示位置时对象还是 null，`_shownLeft` 会一直保持 0。

**3. 从"事件驱动"改为"状态评估"**

最初隐藏逻辑挂在 WPF 的 `Deactivated` 事件上，导致**只能生效一次**：
鼠标触碰边缘唤回时，窗口只是被移回原位、**并没有重新获得键盘焦点**，
于是 `Deactivated` 再也不会触发，隐藏逻辑永久失效。

改为单一 `_watchTimer`（120ms）持续评估真实状态：

```
规则 ①：已隐藏 + 指针进入边缘感应区  → 滑回显示（每个隐藏周期只触发一次）
规则 ②：已显示 + 指针仍在边缘区或窗口内 → 保持展开，并持续重置倒计时
规则 ③：已显示 + 指针离开边缘与窗口 + 窗口非激活 → 开始倒计时，超时后隐藏
```

**关键设计**：边缘感应区（屏幕最右 2px）与隐藏后露出的 peek 条（最右 3px）
在几何上是重叠的。若把"指针在边缘"仅当作唤回触发器，会形成自激死循环：

```
隐藏 → 指针在边缘 → 唤回 → 指针在窗口外 → 延迟到期 → 隐藏 → 无限循环
```

正确做法是让**"指针在边缘感应区"直接抑制隐藏**，而不是让它间接满足隐藏条件。
同时配合 `SHOWN_GRACE_MS = 600` 宽限期，留出时间让鼠标移进窗口。

## 四、组件调整

### 4.1 停用行情组件（StockWidget）

原行情组件（BTC / XMR / SP500 / 黄金）存在数据源不稳定的问题，加载经常失败。

**处理方式**：仅停用、保留源码，便于将来恢复。

- 从 `gtt-sidebar.csproj` 移除 `Compile` 与 `Page` 条目
- `WidgetManager` 移除 `"Stocks"` 的排序与并行初始化分支
- `MainWindow.xaml.cs` 移除相关 `using`
- **源码文件保留在 `Widgets/StockWidget/`**，恢复时只需把条目加回 `csproj`

### 4.2 新增系统信息卡片（SystemInfoWidget）

填补行情移除后空出的竖向空间，数据全部来自本机，不依赖任何外部接口。

| 显示项 | 说明 |
|---|---|
| 运行时长 | 开机时长，如 `3天 5小时` |
| 磁盘可用 | C 盘 `剩余 / 总量 GB` |
| 网络 | 自动识别有线/无线 + 链路速率，过滤虚拟网卡 |
| 进程数 | 当前进程总数 |

刷新频率 5 秒（本地读取，开销极小）。

> **技术细节**：.NET Framework 4.7.2 **没有** `Environment.TickCount64`，
> 改用 P/Invoke `kernel32!GetTickCount64` 获取 64 位开机时长，
> 避免 `Environment.TickCount` 的 49 天溢出问题。

### 4.3 新增日历卡片（CalendarWidget）

放在时钟下方（日期信息相邻），显示当月月历与节假日。

**界面形式**：

- 月历网格 7 列（周一起始），今日蓝底白字高亮
- 放假日：红色小圆点 + 日期数字标红；调休日：灰色小圆点
- 每格悬停显示「日期 + 节日名（放假 / 调休上班）」
- 底部一行显示下一个节假日名称与倒计时（`就是今天` / `明天` / `N 天后`）

**节假日数据源**（四级降级，离线可用）：

```
jsDelivr(holiday-cn) → fastly.jsDelivr → timor.tech → 本地缓存
```

主源 `holiday-cn` 由官方放假通知整理、附 gov.cn 出处，无版权限制。
解析层**同时兼容两种 JSON 结构**（holiday-cn 与 timor.tech），任一源可用即可工作。

**刷新策略**（低频定时 + 启动刷新）：

| 时机 | 行为 |
|---|---|
| 启动时 | 拉取一次 |
| 之后 | 每 **24 小时**刷新一次 |
| 缓存 | 写入 `%APPDATA%/DesktopSidebar/holidays.json`，24 小时内直接命中缓存不发请求 |

另有独立的 30 分钟定时器**只负责重绘界面**（刷新"今天"高亮、跨月自动切换），
不产生任何网络请求。并发保护 `_isLoadingHolidays` 避免定时器叠加重复请求。

**跨年兜底**：本年度假期用完后，自动尝试次年数据继续倒计时，跨年无需改动。

### 4.4 合并系统监控到系统信息卡片

原「系统监控」是一个独立的 40px 高组件，只显示 CPU / 内存 / 延迟三项，
与「系统信息」卡片在职能上高度重叠。现将其**合并进系统信息卡片**：

| 项目 | 改造前 | 改造后 |
|---|---|---|
| 组件数量 | 系统信息 + 系统监控（2 个卡片） | 仅系统信息（1 个卡片） |
| 布局 | 系统监控为 3 列并排紧凑样式 | 统一为「左名称 / 右数值」列表行式 |
| CPU / 内存 / 延迟 | 独立组件显示 | 卡片顶部三行，下方加分隔线 |
| 告警阈值染色 | 有 | **保留**（超阈值标红） |
| 悬停查看均值 | 有（当前 / 5 分钟 / 1 小时） | **保留** |
| 刷新频率 | 独立 2 秒 | 沿用「系统监控」设置区的可配置频率 |

**实现要点**：

- 合并后的卡片同时承担两种职责：实时负载（需 2 秒级刷新）与本机信息（相对静态）
- 两者用同一个定时器刷新——本机信息读取开销极小，统一节奏代码更简单
- `SettingsChanged` 事件订阅保留，设置窗口改阈值/频率后立即生效
- 原「系统监控」组件源码保留在 `Widgets/SystemMonitor/`，从 `csproj` 移除注册，
  不再参与编译（与 StockWidget 的处理方式一致）

设置窗口中该区块的标题改为「系统监控（显示于系统信息卡片）」，明确其作用对象。

### 4.5 天气改用 Open-Meteo 免费源

**改造原因**：原实现硬编码了**他人的 OpenWeatherMap API Key**，随时可能被限流或失效。

**新方案**：[Open-Meteo](https://open-meteo.com)，免费、免注册、无需 API Key。

| 对比项 | 改造前（OpenWeatherMap） | 改造后（Open-Meteo） |
|---|---|---|
| API Key | 需要，且为硬编码他人密钥 | **不需要** |
| 中文城市名 | 不支持 | **支持**（输入「杭州」直接可用） |
| 天气描述 | 需自行映射 | 地理编码直接返回中文 |
| 费用 | 免费额度 1000 次/天 | 免费非商用，无额度焦虑 |
| 预报粒度 | 3 小时接口 | 日粒度，直接给出最高/最低温 |

接口：

- 地理编码：`geocoding-api.open-meteo.com/v1/search?name=<城市>&count=1&language=zh`
- 天气预报：`api.open-meteo.com/v1/forecast?current=temperature_2m,weather_code&daily=...&forecast_days=4`

WMO 天气代码独立映射为中文描述与 emoji 图标；预报取索引 1..3（跳过今天），
显示"最高/最低"双温度。点击城市名可随时更换，中英文输入均可。

## 七、构建修复

**修复了原工程文件的一个缺陷**：`gtt-sidebar.csproj` 中
`Widgets\Shortcuts\ShortcutsWidget.xaml.cs` 被**重复声明**两次，
会导致编译报 `MSB3105` 错误。已删除重复条目。

### 程序改名

编译产物由 `gtt-sidebar.exe` 更名为 **`DesktopSidebar.exe`**：

| 项目 | 改造前 | 改造后 |
|---|---|---|
| 程序集名（`AssemblyName`） | `gtt-sidebar` | `DesktopSidebar` |
| 程序标题 / 产品名 | `gtt-sidebar` | `DesktopSidebar` |
| 窗口标题 | `侧边栏` | `桌面侧边栏` |
| 托盘图标提示文字 | `gtt 侧边栏` | `桌面侧边栏` |
| 开机启动项注册表键名 | `gtt-sidebar` | `DesktopSidebar` |
| **数据目录** | `%APPDATA%/DesktopSidebar/` | **`%APPDATA%/DesktopSidebar/`** |

> **数据目录也同步改名**。为保证改名后不遗留两套目录，原 `%APPDATA%/DesktopSidebar/`
> 中的旧数据已清理，程序会重新生成全新的默认配置。
> 同时新增旧启动项自动清理逻辑：检测到注册表中残留的 `gtt-sidebar` 启动项会自动删除，
> 避免改名后出现重复开机启动。

#### 路径集中管理

数据目录名原本散落在 4 个存储类 + 3 个图标查找处（共 9 处字面量），
改名时容易遗漏。现新增 `Core/AppPaths.cs` 统一定义：

```csharp
public const string DataFolderName = "DesktopSidebar";
public static string AppDataPath      => %APPDATA%/DesktopSidebar
public static string IconsPath        => %APPDATA%/DesktopSidebar/icons
public static string DefaultIconsPath => %APPDATA%/DesktopSidebar/DefaultIcons
```

所有存储类与图标查找均改为引用此常量，后续再改名只需改一处。
